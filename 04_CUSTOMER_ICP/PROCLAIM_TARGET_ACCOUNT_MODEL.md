# PROCLAIM TARGET-ACCOUNT MODEL

## Goal
Build a target market based on evidence of likely Proclaim dependency and operational pain.

## Do not claim a complete current installed-base list
Public sources are incomplete and many historical Proclaim customer announcements are old.
Instead create a scored target-account database.

## Evidence categories

### A — Current direct evidence
Examples:
- current careers page says firm operates Proclaim
- recent job advert requires/desires Proclaim
- current vendor/integration page names firm
- current technical documentation references Proclaim

### B — Historical direct evidence
- old implementation announcement
- old case study
- historical partner page

Must be re-verified before outreach.

### C — Indirect evidence
- recruiter job advert
- employee LinkedIn/job history
- integration-provider claims

Needs confirmation.

## Target scoring

Score 0–5:

### Proclaim confidence
5 = current direct proof
4 = recent strong indirect proof
3 = historical direct proof
2 = weak indirect
1 = possible
0 = no evidence

### Operational density
- PI / claims volume
- headcount
- case-handler count
- multiple branches
- high caseload

### Automation fit
- email-heavy
- document-heavy
- repetitive workflows
- claims portals
- evidence gathering
- chasing

### Commercial fit
- estimated 50–250 users
- operations/IT leadership
- budget
- growth
- active recruitment
- modernisation signals

### Trigger
- hiring admin/file handlers
- system migration
- merger
- growth
- Access/Evo decision
- IT role vacancy
- complaints/support burden
- automation hiring

## Account record
Each account:
- firm
- URL
- locations
- estimated headcount
- practice areas
- Proclaim evidence
- evidence date
- evidence source
- likely Proclaim users
- buyer
- champion
- trigger
- score
- next validation action
