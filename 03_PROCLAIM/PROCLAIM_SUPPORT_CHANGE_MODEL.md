# PROCLAIM SUPPORT & CHANGE MODEL

## User-reported evidence
A 2025 forum thread includes multiple independent users reporting:
- support tickets open for months
- Premier plan not necessarily resolving all delays
- charges/flex points associated with updates/fixes
- frustration with annual cost increases
- perceived dependence on specific knowledgeable support staff

A 2024 thread reports:
- six-week delay obtaining upgrade information
- quoted £1,100 in-hours / £2,200 out-of-hours for a major upgrade
- support sometimes taking months

These are user reports and not universal verified service levels.

## Product/business lesson
A serious replacement should make:
- normal configuration customer-owned
- changes testable in sandbox
- workflow deployment self-service
- documentation complete
- support status transparent
- version upgrades automatic where safe
- pricing for professional services predictable
- backward compatibility explicit

## Support operating model target
### L1
Fast user/help-centre questions.

### L2
Configuration/integration.

### L3
Engineering defects.

### Security
Separate security incident path.

## Customer commitments to eventually define
- severity definitions
- first response
- update cadence
- workaround target
- resolution target where controllable
- escalation
- service credits where appropriate
- status page
- RCA/postmortem for severe incidents

## Strategic opportunity
"Software that changes without a consultant" may be more valuable than "more features."
