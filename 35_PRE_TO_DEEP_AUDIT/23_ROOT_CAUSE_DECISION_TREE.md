# ROOT-CAUSE DECISION TREE

For each pain:

1. **Does native Proclaim already support it?**
   - Yes → why not configured/used?
   - Partial → identify exact missing gap.
   - No/unknown → technical validation.
2. If supported, is the blocker:
   - configuration debt;
   - training/adoption;
   - policy/approval;
   - internal change capacity;
   - licence/module;
   - integration;
   - data quality?
3. If not internally controllable, is it an external dependency?
4. Does the task require legal judgement?
5. What part can safely be standardised/automated?
6. Is the resulting product repeatable across firms?

Only “missing software / repeatable integration layer” should automatically strengthen the software thesis. Other causes may support a services/configuration product instead.
