# PROCLAIM IMPLEMENTATION MATURITY AUDIT

Before saying “Proclaim cannot do X,” inspect:
- exact version/build/environment;
- standard vs forked/legacy case types;
- linked actions, Maths Editor and diary automation;
- current templates;
- history discipline;
- operational reports;
- user profile settings and permissions;
- licensed/unused modules/integrations;
- internal Proclaim developer/admin capability;
- request-to-production lead time;
- UAT/change-control quality;
- support/consultant dependency;
- user training/adoption;
- performance/Office/Outlook friction;
- data quality;
- CaseMatters Evo plans.

Access itself recommends auditing installed case types to determine whether relevant information/templates are being captured, and current Proclaim documentation shows native workflow/diary programmability. Therefore a “manual task” is not evidence of a product gap by itself.
