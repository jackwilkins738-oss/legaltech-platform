# EVIDENCE → DECISION PROTOCOL

## Purpose
Stop the repository becoming a pile of research that never changes decisions.

## Every material new observation gets:
- evidence type
- date
- source
- claim
- confidence
- affected hypothesis
- decision implication

## Evidence types
MEASURED
OBSERVED
VERIFIED FACT
REPEATED USER REPORT
SINGLE USER REPORT
CUSTOMER STATEMENT
ASSUMPTION

## Decision states
PROVISIONAL
VALIDATED
REJECTED
BLOCKED
SUPERSEDED

## Update rule
A later decision must state:
- what changed;
- which evidence caused it;
- what old file/assumption is now superseded.

## Examples

### TO finds 35% of admin time is records chasing
Effect:
increase Records Orchestration score.

Does NOT automatically mean build it.
Still require:
technical feasibility + buyer validation.

### Proclaim task creation API is RED
Effect:
inbound V1 may file content and create task only in our layer / user-trigger flow.

### External firms say inbox filing is already automated
Effect:
decrease inbound wedge score; investigate what partner configuration lacks.

## Weekly founder review
Review:
- decisions changed
- unknowns closed
- new blockers
- experiments required

Do not reread the entire repository weekly.
