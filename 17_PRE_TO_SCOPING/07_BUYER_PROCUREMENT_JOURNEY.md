# BUYER & PROCUREMENT JOURNEY

## Goal
Know the entire path from first conversation to production before outreach begins.

---

# Stage 1 — Target

Evidence:
- Proclaim use
- high-volume workflow
- relevant practice area
- scale
- current trigger

People:
- COO / Ops Director
- Practice Head
- IT Director / Apps
- Managing Partner

Output:
qualified account hypothesis.

---

# Stage 2 — Discovery

Prove:
- repeated workflow
- cost/volume
- process owner
- technical environment
- current workaround
- urgency

Do not demo first.

Output:
quantified problem statement.

---

# Stage 3 — Workflow / ROI Assessment

Map:
- current steps
- time
- systems
- exceptions
- errors
- dependencies

Build:
- baseline
- proposed automation boundary
- ROI range

Output:
pilot business case.

---

# Stage 4 — Product Demonstration

Demo their workflow, not generic AI.

Show:
source item
→ system understanding
→ exception
→ approval
→ Proclaim write-back
→ audit
→ management metric.

Output:
champion alignment.

---

# Stage 5 — Technical Review

IT questions:
- architecture
- Graph scopes
- Proclaim connection
- identity
- hosting
- tenant isolation
- logging
- support

Artifacts:
- architecture diagram
- permission list
- integration spec
- data flow

---

# Stage 6 — Security / Privacy / Compliance

Likely participants:
- IT/security
- DPO
- COLP/compliance
- procurement

Artifacts:
- DPA
- subprocessor list
- security overview
- AI data-use statement
- retention/deletion
- incident response
- pen-test status
- insurance
- BCP/DR

---

# Stage 7 — Commercial / Legal

Agree:
- pilot scope
- price
- liability
- data processing
- success criteria
- termination
- annual pricing hypothesis

---

# Stage 8 — Pilot

Governance:
weekly metric review.

Measure:
- accuracy
- human review
- handling time
- exceptions
- writeback
- incidents
- adoption

---

# Stage 9 — Decision

PASS:
annual contract / expand.

ITERATE:
specific remediation.

FAIL:
stop.

---

# Stage 10 — Expansion

Potential:
- more mailboxes
- more teams
- more workflows
- Matter Command
- evidence services
- client updates
- practice packs

---

# Common objections and required answer

## "Proclaim can already do this."
Need:
comparison based on actual customer configuration/time-to-change, not generic claims.

## "Access will build it."
Need:
speed/cost/ownership/integration comparison.

## "We're going to Evo."
Need:
coexistence and Evo compatibility position.

## "We can't send data to AI."
Need:
provider controls, ZDR/retention, minimisation, human controls.

## "Copilot will do this."
Need:
explain difference between assistant and integrated legal operations execution.

## "You're a startup."
Need:
security pack, insurance, architecture, limited pilot scope, exportability.

## "Another system creates more work."
Need:
Microsoft/Proclaim embedded workflow and measurable touch reduction.
