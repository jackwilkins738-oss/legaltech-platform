# TOMORROW DECISION GATES

## Goal
Use TO observations immediately without overreacting to one day of data.

---

# Gate 1 — Is there a high-frequency expensive workflow?

PASS if early observations show at least one workflow:
- repeated across multiple users,
- consumes meaningful active minutes,
- appears substantially standardised.

If NO:
continue observation; broaden roles/practice areas.

---

# Gate 2 — Is inbound operations still leading?

Compare:
- email/document filing
- task creation
- chasing
- evidence
- status updates
- case review
- intake

Do not lock because we already researched inbound email.

---

# Gate 3 — Is the work automatable?

Strong signal:
- rules repeat,
- inputs structured enough,
- exceptions identifiable,
- judgement low/moderate.

Weak signal:
- every case requires interpretation.

---

# Gate 4 — Is Proclaim technically augmentable?

Use validation matrix.

If GREEN/AMBER:
continue.

If RED on critical writes:
explore read-only or alternate wedge.

---

# Gate 5 — Can a pilot be safely bounded?

Need:
- one team
- one/few mailboxes
- specific matter types
- clear approvals
- measurable baseline.

If pilot requires entire firm:
bad first wedge.

---

# Gate 6 — Is potential value large enough?

Initial test:
Could this plausibly create:
- £30k+ annual value at a midsize team?
- £100k+ at larger customers?

If not, it may be useful but not a strong company wedge.

---

# Gate 7 — Does it create expansion context?

Prefer workflows that give us:
- matter events,
- documents,
- tasks,
- evidence state,
- client communication.

Those unlock more modules.

---

# Decision outcomes

## CONTINUE
Inbound operations remains strongest.
Proceed to technical spike + external validation.

## REORDER
Another workflow clearly dominates.
Update V1 wedge.

## SPLIT
Inbound is useful but another service should be bundled for compelling ROI.

## STOP
No repeated/expensive/buyable workflow.
Do not build merely because research was extensive.

---

# Day-one caution
One day can reveal obvious patterns but not stable averages.

Use tomorrow to:
- identify candidate winners;
not
- pretend estimates are statistically final.
