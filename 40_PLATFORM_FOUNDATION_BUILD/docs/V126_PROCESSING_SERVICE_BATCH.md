# V126 processing HTTP, shared drain boundary and supervised service

This is an authorised D-018 security integration exception. The pre-TO freeze and customer-data deployment gate remain in force. Nothing here deploys a service, selects a real shared control backend, proves real provider permissions or authorises customer data. No schema migration is introduced; all 54 pinned migration checksums remain unchanged.

## Production composition

`createPostgresProcessingService` creates the actual V125 six-pool managed pipeline, its registered thirteen-gate production readiness, a dedicated processing HTTP server and a lifecycle that schedules fresh synthetic canaries. Deployment supplies `processing` (the V125 domain, worker, artifacts, independent queue reader and synthetic canary options), `drain` (the shared backend, current authorizer and deployment ID), `http` (verified identity, shared limiter, current request authorization and durable audit), `probes` (all thirteen production probes) and optional readiness/canary timing. Domain and worker options must omit `drain`; HTTP options cannot override handlers, readiness, drain or lifecycle admission.

The root binds one managed drain to relay, workers, HTTP and DEPLOYMENT_DRAIN readiness. It retains all required production gates, including real managed artifact access, running queue/worker posture and fresh current synthetic canary evidence. Construction does not connect pools, listen or run jobs. `start({port,host,actorId,timeoutMs})` is explicit; host defaults to loopback. Deployment owns TLS, external routing, credentials and pools. Only the two routes below are exposed; this server does not replace the existing application UI, matter/work APIs, identity exchange, Graph ingress, uploads or legacy platform endpoints.

Periodic canaries use the actual V125 synthetic submit/relay/load/execute/receipt/adopt path. Only one canary runs at a time, the next timer starts after settlement, and evidence is invalidated before and after each run. Scheduling defaults to ten seconds and must be at most half the configured canary freshness window. While a canary is active or failing, readiness denies ingress. An independently approved synthetic tenant, version manifest, bounded fixture creation/retention plan, expected deterministic result and current permissions are required. No customer tenant, document or external write may serve as a canary. Fixture marker callbacks and synthetic test implementations are contracts, not evidence of deployed isolation.

## Metadata-only HTTP commands

The server requires registered production readiness and a registered managed drain, rejects known local identity/session/limiter adapters and requires OIDC or server-session authentication output. Identity and permissions are deployment dependencies; a callback cannot prove its own truthfulness. Capability checks, tenant rate limiting and strict current `authorizeRequest` gates (ADMIT and DISPATCH) precede the actual domain handler. Readiness is checked before authentication and again before dispatch. All production probes must report ready; there is no synthetic fallback.

Both routes require exact `Content-Type: application/json`, no content encoding, a bounded UTF-8 JSON object (default 16 KiB) and one `Idempotency-Key` equal to the lowercase UUID `commandId`. Duplicate security/body framing headers are refused. Tenant and actor are bound exclusively from authenticated identity; body-supplied identity, signals, traces or unknown fields are rejected.

| POST route | Exact JSON fields | Required capability |
| --- | --- | --- |
| `/api/v1/processing/inbound` | `commandId`, `jobId`, `eventId`, `payloadId`, `payloadHash`, `sourceSystem`, `externalEventId` | `inbound:create` |
| `/api/v1/processing/policy-evaluations` | `commandId`, `jobId`, `matterId`, `policyVersionId`, `policyVersionHash` | `policy:evaluate` |

IDs are lowercase UUIDs and hashes are lowercase SHA-256 hex. Source system is MANUAL, MANUAL_UPLOAD or MICROSOFT_GRAPH; the external event ID obeys the existing domain identifier grammar. A domain authorization callback must independently enforce current object/version/matter/provider rights; a route capability is insufficient. These routes reference already released immutable versions and accept no raw document bytes.

Successful responses are HTTP 202 with only `commandId`, `jobId`, `objectId`, `status: ACCEPTED` and `replayed`. Acceptance proves domain/outbox commit, not processing completion, policy approval or an external side effect. Worker/adoption/provider/drain administration and raw results are not HTTP endpoints. Domain traces derive from `http-command:<commandId>` so identical retries preserve the immutable request hash even though each HTTP request has a fresh public trace ID. Keep the same command, job, event and artifact bindings when reconciling; never generate replacement IDs simply because a reply was lost. A changed immutable binding returns 409 COMMAND_CONFLICT.

`audit` must durably record metadata-only ATTEMPT before dispatch and ACCEPTED after verified commit. It receives bound IDs, kind, artifact hash and signal, but no external event ID, document text or queue credentials. An attempt audit failure prevents the handler. A postcommit audit failure, unknown domain commit, malformed receipt or execution deadline returns 503 OUTCOME_UNVERIFIED rather than fabricated acceptance or an automatic-retry instruction. Current domain authority withdrawal returns a sanitized denial. Deployment must investigate unknown outcomes with durable command/receipt evidence.

Request timeout/disconnect aborts the signal but cannot declare a running callback stopped. HTTP retains the concurrency slot and ingress lease until actual handler/audit settlement and exact drain release acknowledgement. Default request deadline is ten seconds and default concurrent business admission is 100. Lost acquisition/release replies close further admission and prevent reuse of that HTTP instance. Liveness and readiness remain metadata-only; liveness is process reachability rather than a business-ready assertion.

## Shared backend contract and uncertainty

`ManagedDeploymentDrain` is a fail-closed adapter boundary, **not a provisioned distributed drain store**. Deployment must implement durable, atomic, deployment-scoped `acquire`, `release`, `status`, `begin`, `resume` and `lookupOperation` on a real shared backend. The test-support backend is process-local synthetic code and is never a production implementation. Every process belonging to one deployment must use the same backend scope. Provider calls require workload authorization, bounded transport behavior and durable access/operation evidence.

`acquire({deploymentId,kind,operationId,signal})` must atomically check ACTIVE and persist a unique lease before returning exact `{token,generation}`. Acquisition by operation ID must be immutable and replay-safe. `begin({deploymentId,operationId,actorId,reasonHash})` must atomically close new acquisition, advance generation and return DRAINING while any process holds a lease, or DRAINED only when none do. ACTIVE status must report `acceptingNew:true`; DRAINED requires zero in-flight leases. Tokens are opaque 16–128 character identifiers; generations and in-flight counts are bounded safe integers.

`release({deploymentId,operationId,lease})` must match both token and generation, remain replay-safe and acknowledge exact `{released:true,token,generation}`. Releases survive drain-generation changes. No timer, heartbeat expiry, deployment restart or worker crash may delete an unsettled-effect lease merely to manufacture DRAINED. Effect settlement requires external reconciliation when the owner cannot attest it. `resume` must use compare-and-swap on `expectedGeneration` and require a globally empty DRAINED state; resume while other processes hold leases is forbidden.

`lookupOperation` must return authoritative exact `{state: ABSENT|HELD|RELEASED, lease}`. ABSENT requires null; the others require the original exact lease. An acquisition/release error may represent a committed operation with a lost reply. The adapter latches this uncertainty and fails readiness rather than trusting a locally empty map. Explicit authorised `reconcile({operationId})` can resolve authoritative absence, acknowledge an already released exact lease, or release a proven held lease. It must never return absence while a remote acquisition can still commit. Control-plane begin/resume ambiguity requires operator reconciliation of the backend and reconstruction of stopped adapters; lease lookup alone cannot clear it. The existing supervisor and HTTP uncertainty latches remain conservative even after backend repair; reconstruct them after reconciliation instead of silently resetting their state.

## Shutdown and probe ownership

`stop({actorId,reasonHash,timeoutMs})` synchronously closes local ingress and canary scheduling, invalidates readiness and aborts work. It stops HTTP/relay/worker/canary and begins the shared drain, then waits for actual callbacks, listener closure, startup/cleanup settlement and globally confirmed DRAINED with zero leases. No pools are closed by this root. A deadline returns `drained:false` and STOP_TIMEOUT while retaining the actual stop task. Subsequent `stop` calls can wait on that same task; they cannot fabricate success or restart an uncertain service. Even a fully stopped instance is single-use: deploy a newly constructed, authorised root only after verified drain reconciliation/resume and fresh canary evidence.

Startup also has a bounded wait. An uncooperative callback keeps startup admitted even after START_TIMEOUT. Shutdown can cancel startup, and every late startup stage checks lifecycle state before proceeding. Failed startup cleanup remains tracked; callers must run authorised stop and verify its drained result before disposing of pools. Neither start failure nor stop timeout authorises forced connection closure.

The common `ReadinessCoordinator` now retains each real provider probe until its callback settles. Timeout, forced evaluation or invalidation cannot overlap a hung probe: checks report CHECK_BUSY and remain unready. Late healthy evidence cannot overwrite an invalidated generation. Nonfinite or backward coordinator time invalidates cached health, including rollback during probe completion. This applies to all thirteen production dependencies rather than only the three V125 wrapper probes.
