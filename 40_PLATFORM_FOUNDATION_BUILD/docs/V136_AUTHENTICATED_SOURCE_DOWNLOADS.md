# V136 authenticated source downloads

V136 groups exact adopted-source downloads, immutable version/evidence verification, current read/document authority, metadata audit, stream/transport containment, optional review-page access and production readiness/shutdown wiring. It continues D-018, the pre-TO freeze and customer-data gate. V131 writeback execution remains paused pending partner evidence. Downloads create no decision, outbox intent or external effect.

## Scope and deployment

Pass optional `reviewDocuments` to the durable processing root alongside `reviewRead`: `{manifest, storage, authorizeDocument, verifyEvidence, audit, probeDocuments, timeoutMs?, maxPending?, maxBytes?}`. Manifest requires resolveVersion/probe; storage requires readVersion/probe. All callbacks are deployment-owned and mandatory. The factory binds the actual V134 reader, shared drain and readiness; overriding reader/drain/readiness/pool/expectedRole or http.reviewDocuments is forbidden. The existing eleven-pool root remains eleven pools (fourteen with Graph); no database role, grant, migration, dependency or subprocessor is added. All 59 migration bytes remain unchanged.

Default timeout is 10 seconds (100–60000 ms), capacity four downloads (1–16), maximum 15 MiB per artifact (configurable downward). Capacity covers actual provider work, iterator cleanup and transfer acknowledgement, including cancelled tasks. Each stream permits at most 4096 nonempty byte chunks. Owned chunk copies plus a final buffer mean bounded transient memory can approach twice maxBytes per active download, excluding SDK-owned buffers. Deployments must choose capacity/size limits for their memory budget.

This path delivers the exact artifact bytes identified by the adopted PROCESS_INBOUND result's artifactHash. A provider may not substitute a related attachment, transformed preview, different document, newest version or separate source hash. If the adopted artifact is a JSON envelope, it is downloaded as that envelope; extracting an attachment or building a preview needs its own independently bound future contract. No inline PDF/browser viewer, content transformation, legal assessment or unsafe parser is introduced.

## HTTP and UI contract

`GET /api/v1/processing/reviews/:eventId/document?resultJobId=:uuid&resultHash=:sha256` requires exactly those two unique query fields, canonical UUIDs/lowercase hash, verified OIDC/server session, both inbound:review and document:read, current request authorization for REVIEW_DOCUMENT/ADMIT, IP/tenant admission and production readiness. Actor/tenant remain session-owned. Bodies, Range requests, unknown/duplicate parameters, invalid pins and caller-supplied resource locations are denied. An absent registered component is opaque 404. Missing, foreign, denied and stale-pin objects remain opaque 404; provider/evidence/audit failures return bounded 503 NOT_READY before transfer. The enabled V135 origin/Fetch Metadata guard also covers downloads.

The review shell marks download availability only when the server has a registered component and the current session has document:read. The control appears only for freshly selected detail, uses that exact adopted result job/hash, and disappears while browsing, submitting, retrying an unresolved decision or clearing the page. It requests the server route with the existing same-origin secure session. It does not expose a storage key/version, public or presigned URL, download bearer grant or browser buffer/object URL. Authorization is repeated by the server on every download.

Every successful response is an attachment with a generated event-UUID filename, full Content-Length, exact x-content-sha256, no-store, nosniff, no-referrer, same-origin resource policy and sandbox/default-none/no-framing CSP. Allowlisted types are PDF, UTF-8 plain text and UTF-8 JSON. PDF must begin with the PDF signature; text/JSON must be UTF-8. These checks are MIME containment, not structural validation or malware scanning. The evidence provider must independently establish clean malware scanning and isolated parser evidence for the exact source version. No untrusted filename or MIME header is interpolated.

## Source and authority boundary

The reader first verifies current active human/tenant, object scope and exact adopted result pins. Only then does the manifest provider receive that bound request. Its exact primitive manifest fields are tenantId, eventId, resultJobId, resultHash, artifactHash, objectKey, versionId, size, contentType, evidenceHash, region, revision, state, malwareScan and parserIsolation. Identity/result/source hashes must match the reader; objectKey must be a canonical path inside that tenant prefix; versions must be immutable non-URL references; size/region/revision are bounded. State must be REVIEW_ALLOWED, malwareScan CLEAN and parserIsolation ISOLATED. verifyEvidence must independently verify those claims and current source mapping, scan/parser evidence and region/retention rules; values in the manifest alone are not evidence.

Current authorizeDocument runs at RESOLVE, READ_VERSION and RELEASE, with the session actor and adopted/source pins. It must independently prove current document/matter/source access, including decided objects, rather than copying list capability. Storage is asked for the exact server-resolved key/version, receives a bounded maxBytes and cancellation signal, and must return exactly tenantId/objectKey/versionId/hash/contentLength/body. The response must match the manifest; body must supply an async iterator and explicit cleanup. Bytes are copied, bounded and hashed against the adopted artifactHash. No unverified bytes stream to the client.

Actual iterator cleanup completes before PREPARED audit. After its acknowledgement, the manifest is resolved again and every field compared; evidence is verified again. A final real-reader transaction re-observes the result and active human/tenant, performs RELEASE document authority before its final read authorization/identity checks, and confirms the exact artifact digest before transfer. Audit-time identity withdrawal, source replacement, stale result pins, current access denial or failed audit/evidence acknowledgement prevent byte release. Checks observe authority at their final boundaries; revocation after authorized transfer begins cannot retract already sent bytes.

Audit phases are ATTEMPT and PREPARED. Their bounded metadata contains result/source bindings and size/type, no bytes, raw storage path/version or provider credentials. PREPARED proves an acknowledged preparation attempt, not client receipt or proof the operator reviewed/opened the document. The review checkbox and later decision remain separate from download evidence.

## Ownership, health and shutdown

A document operation owns local capacity and one shared INGRESS lease through all actual provider callbacks, iterator cleanup and the actual HTTP finish/close event. The deadline, disconnect or stop requests cancellation; none proves a callback or socket operation finished. Failed transfers and cancelled tasks wipe only managed copies after actual settlement; SDK-owned buffers remain untouched. HTTP finish acknowledges the server write, not client receipt. Synchronous write failure waits for actual socket close; JSON error/timeout code never attempts to overwrite already-sent binary headers.

Unacknowledged lease acquisition/release, an uncloseable stream, failed cleanup or cleanup without done:true latches uncertainty. Probe/restart/shutdown cannot declare success from that state; deployment must reconcile/reconstruct safely. Delayed callbacks/cleanup/transport events remain owned regardless of the deadline. Document stop joins tasks and all probe siblings; mandatory WORKER_AUTHORIZATION readiness includes actual reader posture, manifest/storage health and the evidence-provider probe. Health saturation counts admitted operations; an admission reservation cannot reject its own readiness check. Saturation or cancelled owned work is unhealthy; probes do not overlap or discard slow siblings.
