# OPEN-SOURCE LICENSING & SOFTWARE SUPPLY CHAIN

## Security is not enough
Dependency can be secure but create licence/IP obligations.

## Controls
Maintain SBOM including:
- package;
- version;
- licence;
- source;
- direct/transitive;
- vulnerability state.

## Licence policy
Pre-approve:
- permissive licences typically acceptable subject to notices.

Review:
- copyleft;
- AGPL/network copyleft;
- source-available/non-open licences;
- commercial restrictions.

Never assume GitHub availability means commercial-use permission.

## Contractor code
Require disclosure of:
- copied code;
- third-party components;
- AI-generated code usage where material;
- licence obligations.

## Dependency governance
- lockfiles;
- automated vulnerability scanning;
- signed/provenance builds where practical;
- dependency pinning;
- emergency patch process.

## Enterprise diligence
Be able to provide:
- SBOM;
- licence policy;
- dependency-management process.
