# MIGRATION STRATEGY

## Strategic view
Migration is one of the strongest potential moats.

A firm may hate its existing PMS and still refuse to move because:
- years of documents
- custom fields
- workflows
- accounts
- permissions
- history
- integrations
- staff familiarity

## Migration product requirements
1. Discovery scanner
2. Schema inventory
3. Data-quality report
4. Mapping layer
5. Transformation rules
6. Document transfer
7. Hash/integrity checking
8. User/role mapping
9. Permission mapping
10. Matter-history preservation
11. Workflow-state conversion
12. Exception report
13. Reconciliation
14. Rehearsal/dry run
15. Delta migration
16. Parallel run
17. Cutover
18. Rollback
19. Sign-off
20. Customer export from our platform

## Principle
Do not build a product that is easy to enter but impossible to leave.
Exportability increases enterprise trust.

## Near-term use
Even before replacing Proclaim, create a clean canonical internal data model.
This reduces future migration cost.
