# SUPPORT RUNBOOK / KNOWLEDGE BASE

## Intake fields
- customer;
- user;
- matter ID only if necessary;
- symptom;
- time;
- screenshots/log reference;
- severity;
- data/security concern?

## Severity
P1:
security, cross-tenant, platform/data integrity.

P2:
major workflow/integration unavailable.

P3:
limited issue/workaround.

P4:
request/question.

## First response
- acknowledge;
- severity;
- workaround;
- owner;
- next update.

## Diagnostics
Prefer:
- trace IDs;
- event IDs;
- connector health;
- redacted metadata.

Avoid asking customers to email confidential raw documents unless approved secure process requires it.

## Knowledge article format
- symptom;
- affected versions;
- cause;
- safe diagnostic;
- resolution;
- escalation;
- last reviewed.

## Escalation
Support → engineering → security/privacy → executive depending on issue.

## Support access
No standing content access.
Customer-authorised, time-scoped, audited.
