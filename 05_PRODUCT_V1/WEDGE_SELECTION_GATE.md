# FIRST WEDGE SELECTION GATE

## Accept only if
- Repeatedly observed
- Quantitatively expensive
- Users feel the pain
- Buyer understands the value
- High frequency
- Measurable outcome
- Coexists with Proclaim
- Does not require full-stack replacement
- Security risk manageable
- High-risk errors can be contained by human approval
- Expands into adjacent workflows

## Reject if
- Full Proclaim replacement required before value
- Depends on unproven API access
- Legal judgement is the main automation
- Error consequences unacceptable
- Low frequency
- No budget owner
- Existing Proclaim configuration solves it adequately

## Required evidence
20+ observed instances; multiple affected users; baseline time; exception map; technical feasibility; 3 external confirmations; 1 serious pilot conversation.

## One-sentence test
'We reduce [specific workflow cost/time/error] for [specific role/firm] by [target outcome] without requiring the firm to replace Proclaim.'
