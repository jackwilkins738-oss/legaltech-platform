# TASK & ACTION TAXONOMY

## Why
Automation becomes brittle if every workflow creates free-text tasks.

Create canonical action types.

## Core task classes

### REVIEW
- review inbound correspondence
- review medical evidence
- review liability response
- review offer
- review court order

### REQUEST
- request records
- request evidence
- request client information
- request expert report
- request defendant disclosure

### CHASE
- chase client
- chase insurer
- chase medical provider
- chase expert
- chase opponent
- chase court/third party

### PREPARE
- prepare letter
- prepare witness statement
- prepare schedule
- prepare bundle
- prepare expert instruction

### APPROVE
- approve outbound email
- approve document
- confirm deadline
- confirm matter match
- approve field change

### SUBMIT/SEND
Initially normally human-controlled:
- send correspondence
- submit form
- serve document

### CALL/CONTACT
- client call
- provider call
- insurer call

### ADMIN
- file document
- update details
- close matter
- archive
- ID check

## Task fields
- tenant
- matter
- class
- subtype
- owner
- team
- due
- priority
- source event
- workflow run
- status
- risk
- approval policy
- automation eligibility
- external dependency

## Benefit
Canonical actions enable:
- reporting
- automation
- SLA
- workload balancing
- reusable workflows
