# OBSERVER INSTRUCTIONS

## Unit of observation
One **task event**, not one matter.

Bad:
"Worked on a PI file for 20 minutes."

Good:
"Opened insurer email → searched Proclaim → matched matter → dragged email to history → renamed attachment → created action."

## Record
- role
- practice area
- task category
- short generic description
- trigger
- active minutes
- waiting minutes
- systems touched
- number of system switches
- approximate steps/clicks
- judgement level
- automation level
- exception?
- rework/error?
- supervisor-review minutes
- estimated frequency
- estimated people doing same task
- confidence
- generic notes

## Timing
Measure **active handling time** separately from waiting.

Example:
- 4 minutes staff work
- 9 days waiting for medical records

Record both.

## When task branches
If one task clearly becomes a separate workflow, create another observation.

Example:
1. File email.
2. Create chase task.
3. Call provider.

## Do not interrupt constantly
Observe first. Clarify after task if needed.

Useful follow-up:
- "Is that the normal path?"
- "How often does that happen?"
- "What happens when that goes wrong?"
- "Does everyone do it the same way?"
- "Could Proclaim already automate any part of this?"
- "Who checks this afterward?"

## Sample target
Day 1:
- 30+ task events
- multiple roles if available
- repeated observations of top tasks
- at least some exceptions

Do not chase statistical perfection on the first day.
