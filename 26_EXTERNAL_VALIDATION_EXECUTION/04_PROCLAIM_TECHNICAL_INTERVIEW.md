# PROCLAIM / APPLICATIONS TECHNICAL INTERVIEW

## Aim
Separate:
- Proclaim limitation;
- bad configuration;
- lack of internal resource;
- support/change problem;
- user training;
- genuinely external workflow.

## Questions
1. Current version / hosting?
2. Current modules?
3. REST/SOAP/web services?
4. Which third-party integrations exist?
5. How are emails posted today?
6. How are docs represented/stored?
7. Can workflows create/modify actions reliably?
8. How are custom fields/screens governed?
9. How are releases/change requests tested?
10. What breaks after upgrades?
11. What is the development backlog?
12. Which user requests are rejected because they're too expensive/time-consuming?
13. What is easier in Proclaim than outsiders realise?
14. What is genuinely hard/impossible?
15. Is CaseMatters Evo being evaluated?

## Critical evidence
Ask for no confidential details.
We need capability and architecture facts, not customer matter data.

## Disqualifying insight
If multiple good Proclaim teams say the proposed wedge is already easy, cheap and reliable to configure natively, downgrade the wedge.
